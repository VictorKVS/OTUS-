# Практическая работа — C4 для учебного проекта

## Результат

Подготовить минимальный комплект архитектурных материалов для одного проекта из репозитория OTUS.

## Этап M0 — минимум

- [ ] выбрать систему и сформулировать её ценность;
- [ ] перечислить пользователей и внешние системы;
- [ ] построить System Context;
- [ ] построить Container diagram;
- [ ] добавить названия, назначения, технологии, стрелки и легенду;
- [ ] проверить схемы по чек-листу.

Критерий готовности: новый участник за 5 минут понимает назначение системы, её границы и основные части.

## Этап M1 — рабочий уровень

- [ ] построить Component diagram для одного ключевого контейнера;
- [ ] добавить Dynamic diagram для важного сценария;
- [ ] обозначить данные, протоколы и доверительные границы;
- [ ] описать три основных архитектурных риска;
- [ ] сохранить исходники диаграмм рядом с документацией.

Критерий готовности: диаграммы позволяют провести архитектурный и ИБ-обзор.

## Этап M2 — продвинутый уровень

- [ ] добавить Deployment diagram для DEV и PROD;
- [ ] связать элементы C4 со владельцами и мерами защиты;
- [ ] автоматизировать проверку или генерацию части модели;
- [ ] добавить ADR с обоснованием архитектурных решений;
- [ ] включить проверку актуальности в CI.

Критерий готовности: документация воспроизводима, проверяема и обновляется вместе с системой.

## Контрольные вопросы

1. Почему C4 Container не равен Docker container?
2. Когда Component diagram не нужна?
3. Почему Code diagram лучше генерировать по требованию?
4. Чем System Context отличается от System Landscape?
5. Как Dynamic diagram помогает моделировать угрозы?
6. Какие данные нужны на каждой стрелке?
7. Что должно быть в легенде?
8. Как связать C4 с журналом архитектурных решений?
