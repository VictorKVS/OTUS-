## Краткий блок для HH/LinkedIn
Проектирую SADEQ/FATHER — корпоративную платформу для создания и безопасного использования AI-агентов. Разработал концепцию универсального объектно-событийного ядра, декомпозицию на 8 функциональных блоков, 12 алгоритмов обработки событий и agent workflow, API-first/Contract-Strict модель взаимодействия, архитектуру локального GraphRAG, контур авторизации UAG и независимой квалификации POLYGON. Формирую трассируемую документацию по ГОСТ 34/ЕСПД и Secure SDLC с каталогом 100 проектных угроз и негативных сценариев испытаний. Проект находится на стадии HLD/LLD и подготовки MVP, без заявлений о production-внедрении.

**Компетенции:** AI Architecture · LLM/RAG · GraphRAG · Python/FastAPI · Agentic workflows · API-first · C4/ADR · Threat Modeling · DevSecOps · Docker/Kubernetes · Secure SDLC · ГОСТ 34/ЕСПД.

## Кейс — три уровня объяснения
### 20 секунд — для HR
SADEQ — мой флагманский инженерный проект: платформа, которая позволяет проектировать корпоративных AI-агентов с единой памятью событий, безопасными инструментами и независимыми испытаниями. Я занимаюсь архитектурой, алгоритмами, безопасностью и планированием реализации.

### 90 секунд — для CTO
Типичный RAG-агент — это один сценарий. SADEQ решает задачу многократного использования платформенных компонентов. Мы разделяем источники, события, состояние объектов, GraphRAG, анализ, проверку полномочий и выполнение действий. Каждая граница имеет алгоритм, типизированный API и проверяемую политику. Модель предлагает гипотезы, но не утверждает себе права и не выпускает себя в production. По 31 уроку OTUS проект увязан с C4, SEDA, API, локальным LLM inference, CI/CD, Kubernetes, безопасностью, FinOps и квалификацией. Реальная промышленная производительность и безопасность пока не заявляются — для них предусмотрены измерения и независимые тесты.

### 3 минуты — для архитектора ИБ/AI
Начинаем от IDEA+ и бизнес-требований, где ведём матрицу угроз. C4/HLD отделяет функциональные блоки от физического deployment. Трасса события: authenticated source → closed JSON Schema → dedupe → canonical object → append-only event → deterministic state reducer → graph/vector evidence → hypothesis/forecast → typed proposal → independent policy UAG → human approval where required → idempotent execution → outcome reconciliation. Для алгоритмов используем литературные источники с точным указанием метода, сравнение альтернатив и ADR. POLYGON — логически и по полномочиям независимая лаборатория; статус QUALIFIED выдаётся только по реальным E2E/negative тестам и версии артефакта. Для строгого on-prem MVP исключён внешний AI API.
