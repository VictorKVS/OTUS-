# SADEQ — дизайн-система инженерного флагманского кейса
**Цель:** яркий, современный, но достоверный и корпоративно-сдержанный портфолио-проект.

## Визуальная идентичность
- Фон: midnight navy #09101e, панель #111d32, светлая подложка для печати.
- Акценты: cyan #36dbd0, blue #4b8dff, restrained violet #a995ff.
- Шрифт: system sans-serif (без привязки к коммерческим шрифтам); плотная сетка 12 колонок, 8px modular rhythm.
- Стиль: enterprise observability cockpit + архитектурные системы; без неонового перенасыщения, без анимации ради анимации.
- Визуализации: архитектурная карта, trust boundary, engineering evidence pipeline, threat catalog by class, дорожная карта G00–G12.
- Доступность: WCAG contrast goal, text labels independent of color, keyboard navigation.
- Маркировка статуса: `DOCUMENTED`, `DESIGNED`, `IN DEVELOPMENT`, `NOT TESTED` — везде, где показатели могут быть ошибочно восприняты как результат.

## Для корпоративной презентации
1. Проблема: дублирование агентообразующих компонентов.
2. Продукт: единое ядро с профилями.
3. Бизнес-сценарий: входящий event → подтверждённая реакция.
4. C4 Context + Container — объяснить границы системы.
5. Control/Data/Qualification/Ops planes.
6. Contract-Strict and UAG; отсутствие права на self-approval.
7. 100 проектных угроз, а не «100 устранённых».
8. SEDA: требования → источники → алгоритмы → сравнение → решение.
9. ГОСТ/OTUS traceability and qualification.
10. MVP, стадии испытаний, roadmap, риски и гипотезы.
11. Архитектурный вклад автора и доказательства в GitHub.
12. Next engineering milestones, без придуманных KPI.

## Правила качественного портфолио
- Каждая крупная цифра должна иметь измеряемый смысл. Например, `8 логических блоков`, `12 описаний алгоритмов`, `100 угроз в каталоге` — это **содержимое проектной документации**, не эффективность платформы.
- Не использовать чужие логотипы как подтверждение партнёрства.
- Инвесторская версия добавляет TAM/SAM/SOM и финмодель **только после проверки гипотез**.
- PDF/презентация должны генерироваться из той же спецификации и не расходиться с GitHub.
- Техническая версия содержит ссылки на evidence, ADR, исходники, конфигурации и ограничения.
