## Принципы
1. Нельзя превращать заранее написанный тест в обоснование уже существующего кода. После согласования эталона тест разрабатывается отдельно от реализации.
2. Источники фиксируются **с точным применимым пунктом**. Там, где пункт не подтверждён, явно ставится `CLAUSE_REVIEW_REQUIRED`.
3. Нормативная база по испытаниям АС — актуальные российские ГОСТ Р 59792-2021 и ГОСТ Р 59795-2021, а не утративший силу ГОСТ 34.603-92.
4. У каждого TEST есть preconditions, environment manifest, test data provenance, source requirements, steps, expected result, negative assertions, failure consequences, evidence IDs and review.
5. Непройденный тест остаётся FAIL, неразработанный — NOT_RUN, заблокированный — BLOCKED. `pytest -q` сам по себе не квалифицирует систему.
6. Допуск на уровень P0 определяется ТЗ, не «процентом зелёных галочек»: критические отказы по безопасности закрывают допуск.
7. Схемы Mermaid — предварительные редактируемые источники, не утверждённые формальные схемы по ЕСПД.
