## Правило матрицы угроз
THR ledger создаётся при DG-00 в IDEA+, затем к каждой записи добавляются asset, risk owner, controls, ALG/CMP/FLOW, test, evidence, residual risk, sign-off. Новая угроза может впервые появиться на любой стадии; история не стирается. `THR-001..100` — исходный **каталог**, не полный нормативный перечень и не 100 уже устранённых угроз.

## Правило испытаний
Программное автономное тестирование → интеграционные проверки → security/AI/POLYGON → развёртывание и инфраструктурные проверки → предварительные испытания системы → опытная эксплуатация → приёмка. Независимый POLYGON является внутренней лабораторией доказательств и **не подменяет** предусмотренную контрактом комиссию.

## Evidence Gate
`REQ-ID → DOC-ID → CMP-ID → ALG-ID → FLOW-ID → THR-ID → TEST-ID → EXECUTION-ENV → BUILD-SHA → RESULT → EVIDENCE-SHA → REVIEWER → APPROVER`.

Statuses: `NOT_STARTED, DRAFT, REVIEWED, APPROVED_DOCUMENT, IMPLEMENTED, TESTED, QUALIFIED, ACCEPTED, REVOKED`; document approval ≠ qualification or acceptance.

## Evolution rule
При изменении схем, алгоритмов, prompt, модели, источников, прав, tool, Docker image, K8s manifest → review impact → reopen relevant risks → rerun tests → reissue qualification before reactivation.
