# FATHER Architect OS — сквозная дорожная карта OTUS 1–31

## Цель

Превратить материалы курса в воспроизводимый конвейер проектирования AI-систем:

`BUSINESS → REQUIREMENTS → HLD → LLD → AI/DATA → SECURITY/QUALITY → SIZING → DELIVERY → RELIABILITY → FINOPS/GOVERNANCE → API PRODUCT`

## Режим разработки

Один последовательный поток. Сначала полный проход M1 по всем 31 урокам, затем профессиональное усиление M2, после этого автоматизация M3.

## Контрольные ворота

| Gate | Уроки | Результат | Условие перехода |
|---|---:|---|---|
| G1 | 01–03 | Vision, требования, риски, смета, план поставки | Ценность, границы и ограничения подтверждены |
| G2 | 04–07 | C4, LLD, RAG/Agent design | Компоненты, связи и AI-паттерны обоснованы |
| G3 | 08–10 | ADR, CTO review, debt register | Ключевые решения проверены |
| G4 | 11–15 | Integration, Data, Quality, Security, Observability | NFR связаны с тестами и контролями |
| G5 | 16–20 | Sizing, IaC, MLOps, CI/CD, Deployment | Ресурсы рассчитаны, rollback испытан |
| G6 | 21–27 | HA/DR, K8s, EDA, High-load, Cloud, Tenancy, Privacy | Масштабирование и восстановление подтверждены |
| G7 | 28–31 | FinOps, Radar, Model Card, Governance, API Product | Экономика и выпуск согласованы |

## Сквозные идентификаторы

- `BUS` — бизнес-цель
- `REQ` — функциональное требование
- `NFR` — требование качества
- `ASM` — допущение
- `RISK` — риск
- `ADR` — архитектурное решение
- `CMP` — компонент
- `DATA` — данные/знания
- `CTRL` — контроль безопасности
- `TEST` — проверка
- `SLO` — эксплуатационная цель
- `COST` — стоимость
- `REL` — релиз

## Правило доказательности

Каждый критический компонент должен иметь цепочку:

`BUS → REQ/NFR → RISK → ADR → CMP → CTRL → TEST → SLO → COST → REL`

## Три уровня зрелости

- **M1 — полный путь:** для каждого урока есть минимальный проверяемый результат.
- **M2 — профессиональный:** метрики, владельцы, источники, альтернативы, риски и трассировка.
- **M3 — автоматизированный:** генераторы, калькуляторы, схемы, валидаторы и выпуск Architecture Pack.

## Ближайший этап

Нормализовать уроки 01–03 и закрыть G1 на сквозном проекте FATHER Architecture Platform.
