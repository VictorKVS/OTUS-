Цели занятия
изучить стратегию реализации проекта;
декомпозировать большую задачу на этапы, каждый из которых приносит измеримую ценность и снижает риски для дальнейшей разработки.
Краткое содержание
этапы поставки ценности: архитектурные компромиссы и бизнес-цели каждого этапа;
демо: проверка гипотезы «как это будет выглядеть» (часто просто фасад);
Proof of Concept (PoC): проверка технической гипотезы, валидация технологий, паттернов и выполнимости («Data Challenge», EDA);
Minimum Viable Product (MVP): проверка рыночной гипотезы с минимальным набором функций для реальных пользователей;
связь стратегии с контрактом: как поэтапная поставка (например, PoC по T&M, а основной проект по FP) помогает управлять рисками и бюджетом;
путь в Production: планирование полного жизненного цикла решения, включая окружения Dev, Test, Prod и их архитектурные особенности;
практика: разработка дорожной карты проекта с AI-рекомендациями, включающей описание бизнес-целей, scope, архитектурных решений и рисков для этапов PoC, MVP и Production.

практическое задание;
конспект лекции.

Домашнее задание
Разработка стратегии, оценка рисков и дорожной карты AI-проекта
Цель:
разработать стратегию внедрения AI-решения с выбором контрактной модели, оценкой рисков и дорожной картой для согласования с заказчиком.

Описание/Пошаговая инструкция выполнения домашнего задания:
Легенда:


Вы — архитектор в компании-интеграторе. Клиент (крупный ритейлер) хочет внедрить AI-систему персонализированных рекомендаций, но требования размыты («хотим как у Ozon»). Описание кейса вы найдёте в доп.материалах к этому занятию.


Шаги выполнения:


1. Анализ требований: На основе легенды сформулируйте 5-7 уточняющих вопросов клиенту для снятия неопределенности.


2. Выбор контракта: Обоснуйте выбор модели (T&M, FP или гибрид) для этапа PoC и для основной разработки. Поясните, почему это выгодно обеим сторонам.


3. Оценка рисков: Составьте матрицу рисков (минимум 5 рисков), специфичных для AI (например, качество данных, галлюцинации модели). Предложите план митигации.


Roadmap: Разработайте дорожную карту. Опишите критерии успеха (DoD) для этапов:


* PoC (проверка гипотезы);
* MVP (выход на пользователей);
* Production (масштабирование).


Полезные материалы:


* Матрица рисков. Пример заполнения
* Шаблон реестра рисков для количественной оценки


Формат сдачи:


PDF-файл (или ссылка на Google Doc/Holst) содержащий:


* Список вопросов.
* Обоснование контракта.
* Матрицу рисков.
* Схему/Таблицу Roadmap.


Если вы отправляете ссылку, то убедитесь, что по ней открыт доступ.


Если у вас возникнут вопросы, вы можете задать их в чате проверки домашнего задания или в группе в VK.

Критерии оценки:
Статус «Принято», если:
1. Обоснованность: Выбор типа контракта логично вытекает из уровня неопределенности.
2. Полнота: Roadmap покрывает все три стадии (PoC, MVP, Prod).
3. Реалистичность: Риски специфичны для AI-проектов, а не общие фразы.
4. Структура: Документ читаем и понятен для бизнеса.

o - аргументированно обосновывать выбор коммерческой модели контракта (FP, T&M, T&M with a cap) для конкретного проекта

o - разрабатывать дорожную карту проекта, декомпозируя задачи на этапы PoC, MVP и Production
