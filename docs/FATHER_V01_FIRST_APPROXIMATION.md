# FATHER v0.1 — First Approximation

## Goal

Prove the engineering spine before visual polish:

TASK → Operator → Project Composer → ALINA → Knowledge → FATHER Core LLM → Routing/Run → LAB → Security → Evidence/Ownership → Result.

## One system

- one FATHER platform;
- one shared ALINA analytical core with domain profiles;
- one controlled FATHER Core LLM profile over replaceable base models;
- one Component Library;
- one LAB;
- one Evidence/Ownership system;
- one Security acceptance boundary;
- one C00–C99 technical dossier.

## Mandatory cross-cutting controls

Every meaningful block or decision carries baseline, A/B/N alternatives where applicable, metrics, tests, evidence, provenance and explicit security state.

Functional PASS is never Security PASS.

## First reference product

A simple controlled assistant. Telegram, voice and avatar are adapters, not the core.

The v0.1 proof is complete only when a task can traverse the full spine and leave an evidence bundle.

## Status truth

This release is FIRST_APPROXIMATION. It defines and wires the skeleton. Individual modules keep their own maturity states; the release does not promote DESIGN, EXPERIMENTAL or CANDIDATE modules by association.
