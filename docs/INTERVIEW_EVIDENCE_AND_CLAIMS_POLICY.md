# Interview Evidence & Claims Policy

## Цель

Различать коммерческий опыт, проектную практику, лабораторную практику и теоретическое понимание.

Маркеры: `WORK`, `PROJECT`, `LAB`, `KNOWLEDGE`, `VERIFY`.

## Можно писать

- «проектировал» — если есть архитектурный артефакт;
- «реализовал прототип» — если прототип запускается;
- «исследовал/тестировал» — если есть lab/eval;
- «использовал в проектной практике» — для portfolio;
- «понимаю назначение и место в архитектуре» — для L1/L2 tooling.

## Нельзя без доказательства

`production-ready`, «в промышленной эксплуатации», точные проценты роста качества, senior-role как коммерчески подтверждённую, экспертность по SIEM/EDR/DLP без hands-on эксплуатации.

## Внутренние названия проектов

В публичном резюме внутренние имена репозиториев заменяются функциональными описаниями: **Engineering AI Platform**, **Knowledge & RAG Platform**, **Multi-Agent Analyst System**, **Security Intelligence / Threat Modeling System**, **Generative AI Media System**.

Название проекта не доказывает компетенцию. Доказательство — задача, архитектура, код, тест, схема или working demo.

## AI-assisted development

Использование coding agents не скрывается. Формулировка: **AI-assisted software development: decomposition, prototyping, code generation, refactoring, testing, documentation and debugging with human review and verification.**

На интервью кандидат должен уметь объяснить любой значимый фрагмент кода, созданный с помощью AI.
