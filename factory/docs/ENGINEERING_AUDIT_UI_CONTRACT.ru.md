# FATHER Factory — требования к интерфейсу справки, трассировки, аудита и памяти

**Статус:** проектная спецификация, не работающая система. Наличие страницы не означает соблюдения требований ФСТЭК или наличие аттестации.

## Рабочие окна
- **Диспетчерская:** проект, занятие, задача, запуск, агент, состояние защиты. Статусы «запланировано», «реализовано», «проверено» различаются.
- **Карточка действия:** назначение кнопки, условия, полномочия, угрозы, нормативные ссылки, ожидаемые результаты, подтверждение и процедура отката.
- **Трассировка:** общая цепочка событий по идентификатору trace_id: интерфейс → API → исполнитель → CI → GitHub → Kubernetes.
- **Доказательства:** коммиты, тесты, журналы, хеши, снимки экрана и отчёты с контролем доступа.
- **Реестр безопасности:** требование → риск → мера → тест → доказательство; выявление незакрытых связей.
- **Журнал решений и ошибок:** описание ошибки, первопричина, разрешённое исправление, повторные испытания и опыт.
- **Память и знания:** утверждения агентов с источниками отдельно от неизменяемого журнала аудита.

## Правила безопасности
Никакого произвольного исполнения команд с веб-страницы: только заранее определённые действия. Проверка личности и прав на сервере, подтверждение рискованных операций человеком, сокрытие секретов, защищённое хранение доказательств, идентификаторы событий, принцип минимальных привилегий, резервное копирование. Сайт не должен показывать успешный запуск без подтверждения реального исполнителя.
