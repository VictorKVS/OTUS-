## Принятое решение

Для текущего учебно-проектного контура основной inference backend — **Self-hosted Open-Source LLM** через LLM Gateway.

Это решение не утверждает, что self-hosted универсально дешевле или качественнее SaaS. Оно принято для текущего контекста: уже существующего локального стека, требования к контролю данных, воспроизводимости и управлению версиями моделей.

## Воспроизводимый TCO-сценарий

Команда:

```bash
python llm_tco_calculator.py
```

Демонстрационные входные предпосылки, зафиксированные непосредственно в скрипте:

- API: 100 000 запросов/мес;
- 2 000 input + 500 output tokens на запрос;
- условные rates: 2 и 8 денежных единиц за 1M tokens;
- on-prem CAPEX: 5 000;
- срок амортизации: 36 месяцев;
- мощность: 0.45 kW;
- 730 часов/мес;
- электроэнергия: 0.15/kWh;
- PUE: 1.2;
- operations & maintenance: 150/мес;
- utilization: 60%.

Результат сценария:

```text
API/month: 800.00
On-prem/month: 348.02
Effective GPU-hour: 0.79
```

**Важно:** это не текущий коммерческий прайс и не универсальное доказательство экономии. Числа служат для демонстрации воспроизводимой методики. Перед реальным решением rates, CAPEX, электроэнергия, utilization, SLA и эксплуатационные трудозатраты должны быть измерены/актуализированы.

## Quality Gate

Экономика сравнивается только после достижения сопоставимого уровня качества и SLO. Если локальная модель дешевле, но не проходит тот же evaluation set по качеству и latency, финансовое преимущество не считается достаточным основанием для выбора.

Минимум для защиты:

1. одинаковый eval dataset для SaaS и self-hosted;
2. quality metrics (например, faithfulness / answer relevancy для RAG);
3. p50/p95 latency;
4. throughput/concurrency;
5. фактическая стоимость или сценарный TCO;
6. требования Privacy/Security;
7. операционные трудозатраты.

## CTO Challenge — короткая линия защиты

1. **Почему не SaaS?** — SaaS сильнее по качеству frontier-моделей и простоте эксплуатации, но хуже соответствует текущим требованиям контроля данных, воспроизводимости и независимости от внешнего API.
2. **Почему self-hosted не “бесплатный”?** — в TCO включены CAPEX, электричество, PUE, эксплуатация, обслуживание и риск недоиспользования GPU.
3. **Что если качество хуже?** — решение имеет quality gate и пересматривается, если локальная модель систематически не проходит общий eval-набор.
4. **Что если нагрузка вырастет?** — выполняется новый capacity/TCO анализ; возможен новый ADR на cloud GPU, SaaS или hybrid.
5. **Как избежать lock-in на Ollama?** — приложение использует собственный LLM Gateway; runtime/model не являются бизнес-контрактом.
6. **Когда решение потеряет силу?** — при изменении SLA, нагрузки, Privacy, стоимости или измеримого качества создаётся новый ADR / superseding decision.

## Правило ADR

После принятия ADR история решения не переписывается. При смене подхода создаётся новый ADR, который supersede-ит предыдущий.
