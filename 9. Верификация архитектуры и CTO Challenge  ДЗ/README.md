# Урок 9. ADR и стоимость LLM-инфраструктуры

## Цель

Научиться фиксировать архитектурные решения в Git и обосновывать выбор между API/cloud и собственной инфраструктурой LLM.

## Содержимое

- `adr/ADR-TEMPLATE.md` — основной шаблон FATHER ADR.
- `adr/ADR-MINIMAL.md` — сокращённый шаблон.
- `adr/0001-cloud-vs-onprem-llm.md` — пример решения.
- `CLOUD_VS_ONPREM.md` — конспект и формулы TCO.
- `llm_tco_calculator.py` — воспроизводимый расчёт сценариев.
- `SOURCES.md` — первоисточники.
- `ADR_TOOLING.md` — каталог инструментов и рекомендуемый стек внедрения.

## Процесс

```mermaid
flowchart LR
    A[Проблема] --> B[Драйверы]
    B --> C[Варианты и расчёты]
    C --> D[Решение ADR]
    D --> E[Проверка реализации]
    E --> F[Пересмотр или новый ADR]
```

## Правило репозитория

Каждое значимое решение получает отдельный неизменяемый ADR. При замене решения создаётся новый ADR со статусом `superseded`, а не переписывается история.
