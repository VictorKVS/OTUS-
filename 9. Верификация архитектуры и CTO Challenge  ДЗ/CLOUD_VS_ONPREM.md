# Cloud vs On-prem LLM: модель решения

Статья a16z подчёркивает преимущества cloud на ранней стадии: меньшие первоначальные затраты, масштабирование и отсутствие необходимости строить инфраструктуру. Собственная инфраструктура становится оправданнее при очень большом масштабе, особом оборудовании, геополитических ограничениях или необходимости полного контроля. Указанные в статье цены относятся к 2023 году, поэтому их нельзя использовать как текущий прайс без повторной проверки.

## Четыре сценария

| Сценарий | Сильная сторона | Основной риск |
|---|---|---|
| Hosted API | Быстрый MVP | Vendor lock-in и стоимость токенов |
| Cloud GPU | Контроль модели без CAPEX | Простой GPU и обязательства |
| On-prem GPU | Контроль данных и предсказуемый CAPEX | Низкая утилизация и эксплуатация |
| Hybrid | Баланс пиков и базовой нагрузки | Сложность маршрутизации |

## Формулы

### Hosted API

`Monthly API = requests × ((input_tokens × input_rate) + (output_tokens × output_rate)) / 1_000_000`

### Cloud GPU

`Monthly cloud = gpu_hour_rate × gpu_count × active_hours + storage + traffic + operations`

### On-prem

`Monthly on-prem = CAPEX / lifetime_months + electricity + cooling + operations + maintenance + facility`

`Electricity = power_kW × hours × electricity_rate × PUE`

### Стоимость полезного GPU-часа

`Effective GPU-hour = total_monthly_cost / (available_hours × utilization)`

### Точка безубыточности

`Break-even months = CAPEX / (monthly_cloud_or_API - monthly_onprem_OPEX)`

Если знаменатель меньше или равен нулю, on-prem не достигает финансовой окупаемости при заданных предпосылках.

## Что обязательно измерять

- запросы и токены по моделям;
- среднюю и пиковую параллельность;
- p50/p95 latency и throughput;
- загрузку GPU и VRAM;
- ошибки, очереди и время простоя;
- стоимость хранения и сетевого трафика;
- трудозатраты эксплуатации;
- стоимость риска простоя и утечки;
- качество ответа на общем eval-наборе.

## Quality Gate

Решение допустимо только при сравнении одинакового уровня качества и SLO. Нельзя объявлять дешёвую локальную модель победителем, если она не проходит тот же набор тестов, что облачная модель.
