# ADR-0001: Начать LLM-проект с API и сохранить путь к локальному inference

## Контекст

Проекту нужен быстрый старт без крупных капитальных затрат, но в дальнейшем могут появиться требования к конфиденциальности, предсказуемой стоимости и локальной работе.

## Варианты

1. Hosted model API.
2. Cloud GPU с самостоятельно развёрнутой моделью.
3. Локальный сервер/GPU.
4. Гибрид: API для пиков и сложных задач, локальная модель для базовой нагрузки.

## Решение

На этапе MVP использовать hosted API, но определить интерфейс `ModelGateway`, вести телеметрию токенов, задержки и качества, а также ежемесячно пересчитывать альтернативы. Переход к cloud GPU или локальному inference выполняется при достижении порогов по стоимости, конфиденциальности либо доступности.

## Последствия

### Положительные

- минимальный CAPEX и быстрый запуск;
- простое масштабирование MVP;
- сбор реального профиля нагрузки до покупки оборудования.

### Отрицательные

- зависимость от провайдера и тарифов;
- ограничения по данным и регионам;
- переменная стоимость при росте токенов.

## Проверка

Ежемесячный отчёт должен содержать запросы, токены, cost/query, p50/p95 latency, error rate, качество и прогноз TCO для четырёх вариантов.

## Триггеры пересмотра

- стоимость API устойчиво выше рассчитанного TCO собственной инфраструктуры;
- требования запрещают передачу данных внешнему провайдеру;
- p95 latency или доступность не выполняют SLO;
- локальная загрузка GPU может удерживаться на экономически оправданном уровне.
